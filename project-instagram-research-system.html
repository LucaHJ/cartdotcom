Design Instagram Research System

Turning saved Instagram posts into a searchable research library with retained source material and linked findings.

Python / Node.js / PostgreSQL / FFmpeg / Cloudflare

  1. Receive a shared post
  2. Extract media evidence
  3. Research and synthesise
  4. Store linked resources

What It Does

The Instagram research system takes shared Reels and supported carousel posts through media extraction and research, then retains the resulting resources in a browsable knowledge library. It connects source material with transcripts, sampled media and synthesis so useful information can be found again.

How It Works

Cloudflare handles intake and durable edge recovery. An Ubuntu processor performs media work and synthesis, with PostgreSQL and local disk as the primary data store. Cloud mirrors support recovery and fallback. Processing separates control state from compute results, with job identities, leases and checkpoints supporting recovery after interruptions.

The broader workflow includes linked Markdown knowledge pages and retrieval. Media processing uses tools including FFmpeg and downloadable source artifacts; results retain their connection to the original post rather than becoming disconnected notes.

What Needed Solving

Moving compute locally did not automatically remove cloud costs. A recovery mirror repeatedly scanned historical rows, and read-only thumbnail requests unnecessarily woke that mirror. Indexed, committed cursors and removing those wakes sharply reduced the work. Another incident left jobs stalled behind a service that appeared healthy: leaked database handles had exhausted its file-handle limit.

Lessons From Development

Service uptime is not the same as progress. Health reporting needed to include queue movement and handover responsiveness. Cost also depends on query shape and wake-up behaviour, not just where the files live. Clear ownership, deterministic cleanup and recoverable checkpoints mattered throughout the cloud-to-local transition.

Current Scope

A personal research and retrieval system with local-primary processing. This page describes the project; private library content, operational controls and account details are not exposed.
