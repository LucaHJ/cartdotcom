Visual programming / Desktop automation

FH6GrindScript

A visual macro editor that reacts to screen content, turning a small pixel-triggered input script into inspectable, reusable automation.

Python / Blockly / JavaScript / pywebview

  1. Capture a visual condition
  2. Compose Blockly actions
  3. Run a matching bind
  4. Inspect active steps

What It Does

FH6GrindScript watches for saved pixel sets or screen states and runs sequences of keyboard actions. Its Scratch-style editor supports presses, timed waits, held inputs, loops, conditional branches and background checks. A global start/stop hotkey controls execution.

How It Works

Blockly provides the editing canvas inside a desktop WebView, while Python handles screen capture, native input and the runtime. A shared JSON project stores captures, bindings and nested steps. Boolean condition blocks can be reused for activation, branching and waiting, with migration from the earlier pixel-only trigger fields.

Each enabled bind has a watcher. Only one bind owns the main execution slot at a time, and its trigger is checked again before actions begin. Runtime block IDs feed status updates back to the editor so the currently executing steps can be highlighted.

What Needed Solving

The first highlighting implementation coloured nested blocks that had not run because its CSS selector reached every descendant. Separately, loop children bypassed the wrapper that tracked active steps. Fixing both paths allowed an outer loop and its executing child to appear together. Short key presses now flash briefly, while waits remain highlighted for their actual duration.

Lessons From Development

A visual programming interface needs a faithful connection between saved blocks, runtime state and feedback. Reusing one condition representation reduced inconsistencies across features. Screen matching also made the limits of visual automation clear: resolution, window placement and animated pixels can change whether a trigger matches.

Current Scope

A Windows screen-content macro editor. Detection uses pixel and screen comparisons; OCR and direct application telemetry are possible extensions, not implemented capabilities claimed here.
