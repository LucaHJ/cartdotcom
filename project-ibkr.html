Automation / Paper trading

IBKR

A paper-trading research and execution system designed to keep working through broker outages without confusing a recommendation with a completed trade.

Python / FastAPI / PostgreSQL / IBKR API / Docker

  1. Schedule research
  2. Persist decisions
  3. Recheck broker and risk
  4. Reconcile orders and fills

What It Does

IBKR combines scheduled portfolio research, a durable execution queue and a dashboard for reviewing decisions, holdings and performance. It operates on a paper account. Research can continue while the broker gateway is disconnected, and a decision to hold is a valid result.

How It Works

A research worker follows the official exchange calendar and saves its report and target allocations. A separate Python execution worker reads the PostgreSQL queue, refreshes holdings, verifies quotes and risk limits, then submits monitored limit orders. The system reconciles uncertain submissions against broker records before retrying.

Performance archives run on the wall-clock hour independently of execution. Reporting can use independent market prices when the gateway is unavailable; submitting orders still requires the broker's execution checks. Reports distinguish research, queued orders and confirmed fills.

What Needed Solving

Integration failures were more subtle than a disconnected gateway. A changed commission field broke an order callback, while account-summary subscriptions were not being cancelled correctly and eventually exhausted the broker's subscription limit. Compatibility handling and repeated read-only refresh checks addressed those failures. Session conflicts and missing FX permissions also required explicit recovery paths.

Lessons From Development

An external API needs testing across repeated calls and partial failures, not just a successful first connection. Durable queues, expiring decisions and order reconciliation make restarts understandable. Separating reporting prices from execution prices also prevents a convenient fallback from silently changing trading behaviour.

Current Scope

A paper-only system with recorded research and order outcomes. The project demonstrates integration and recovery engineering; it does not establish investment profitability or live-trading readiness.
